# Shortest safe release path

1. Preserve original work; audit all existing story modules and local assets. **Done.**
2. Fix missing translations/date locking/parental links/persistence errors without changing story prose. **Implemented; automated checks run.**
3. Generate Expo native iOS/Android projects and real icon assets; compile JS for each platform. **See TEST_REPORT.md for actual build results.**
4. Owner immediately enrolls in Apple Developer, Google Play Console and Expo/EAS, verifies identity and decides publisher name/contact/domain. Do this before optional polish.
5. Install native prerequisites or use EAS managed builders. Build testing profile; install on real phones/tablets and start TestFlight/Play internal testing. For affected new personal Play accounts, run closed testing with at least 12 continuously opted-in testers for at least 14 days; internal testing does not satisfy that gate.
6. Complete public privacy/support pages and store declarations; confirm content rights and audience/rating answers. Capture screenshots from native release candidates.
7. After physical QA, create a production profile build (test unlock OFF), verify signing, native API/SDK versions, privacy manifests and app size.
8. Obtain owner's explicit confirmation before submission/public release. Use manual release after approval; no automatic publication.

No accounts, paid enrollments, contracts, public hosting, store submissions, tester invitations or third-party uploads are performed by this local preparation task.
