# PWA — встановлення, публікація та перевірки

29 жовтня 2026. **Публічне розгортання не виконане. URL ще немає.** Netlify CLI підтвердив відсутню авторизацію. baptistslavic.com не змінювався. Застосунок не переписано: ті самі історії, мови, карта й ключі прогресу.

## Як опублікувати — тільки після дозволу власниці

Для PWA потрібен лише Netlify-акаунт, Apple/Google/Expo акаунти не потрібні.

Готовий пакет: `AdventBibleJourney-PWA-ready.zip` (приблизно 99 МБ). Містить `deploy/dist`, функцію reviewer access, конфігурацію та START.txt. Для цього готового пакета після погодження й входу виконайте команду з START.txt **з --no-build**; для вихідного проєкту нижче збірка виконується автоматично. Це не публічне посилання.

1. Власниця входить у Netlify. На цьому Mac у терміналі проєкту:
   `npx netlify-cli@latest login`
2. Після погодження публічної публікації виконуємо з `app/mobile`:
   `npx netlify-cli@latest deploy --prod --site-name ОБРАНЕ-ВІЛЬНЕ-ІМЯ`
   Замінити ім’я на погоджене ASCII-ім’я сайту. CLI створює/прив’язує проєкт і за поточною версією сам запускає збірку. Не використовувати anonymous deploy чи Netlify Drop: разом зі статичними файлами потрібна функція reviewer access. Не завантажувати весь каталог проєкту як publish directory.
3. У Netlify → Project configuration → Environment variables додати **секрети зі scope Functions**: `REVIEW_PASSWORD` (випадковий приватний пароль щонайменше 20 символів) та `REVIEW_SESSION_SECRET` (незалежний випадковий ключ щонайменше 32 символи). Не додавати префікс EXPO_PUBLIC, не записувати значення в Git/чат/netlify.toml. Після зміни секретів повторити розгортання того самого сайту. Без них звичайне читання працює, але reviewer endpoint відмовляє в доступі.
4. Відкрити фактичний HTTPS URL з результату Netlify; перевірити `/manifest.webmanifest`, `/sw.js`, `/home`, `/settings`, `/advent/1`, `/advent/24` та `/review`. Пароль передається рецензентам приватно, не в описі магазину/публічній інструкції.

Варіант GitHub: після дозволу завантажити зміни у свій репозиторій, Netlify → Add new project → Import existing project → GitHub. Якщо Git-root — поточний каталог `app`, base directory = `mobile`; build command = `npm run build:pwa`, publish = `dist` відносно base. Якщо репозиторій містить тільки mobile, base порожній. Перевірити ці поля до Deploy. Git-інтеграція автоматично публікує наступні push — вмикати лише зі свідомого дозволу.

**Постійний домен вибрати до запрошення родин.** Прогрес прив’язаний до origin браузера: зміна Netlify-субдомену/домену не переносить дані автоматично. Він також не синхронізується з нативним застосунком.

## Встановлення для родини

- iPhone/iPad, Safari: відкрити HTTPS посилання → Поширити → На початковий екран → Відкрити як вебзастосунок (якщо є цей перемикач) → Додати. Потім запускати іконкою. PWA не показує фальшиву кнопку автоматичного встановлення на iPhone.
- Android, Chrome: відкрити посилання → меню → Встановити застосунок / Додати на головний екран. Кнопка в налаштуваннях з’являється тільки якщо браузер справді надав install prompt.
- Дати першому онлайн-завантаженню завершитися. Тексти всіх історій, шрифти й оболонка кешуються; ілюстрації зберігаються під час перегляду. Непереглянуті картинки можуть вимагати інтернет. Браузер/ОС можуть очистити сховище при нестачі місця; не обіцяємо безумовного збереження після очищення даних сайту.

## Дати й рецензенти

Часова політика спільна з native: **локальна календарна дата пристрою**, 1–24 грудня 2026. Місцеві рік/місяць/день переводяться в умовний UTC-номер дня, тому DST не скорочує/подовжує день. До 1 грудня показано привітання з датою старту; 1 грудня доступний день 1, 24 грудня — усі. Завершені дні доступні навіть після зміни годинника/часового поясу. Після сезону лишаються доступними. Це календарне планування, не шифрування контенту/DRM.

PWA: `/review` → приватний пароль → Open all 24 days. Сервер перевіряє пароль і видає підписаний HttpOnly/Secure cookie на 8 годин. Налаштування звичайного неавторизованого читача не мають developer unlock. Preview не записує завершення, завершується після виходу/перезапуску; повторна авторизація потребує мережі. Секрети не входять у dist. Native зберігає попередній явно позначений store-review flow без залежності від Netlify.

## Оновлення без втрати прогресу

1. Внести спільні зміни, запустити `npm run check:release`, `npm run build:pwa`, `npm run test:pwa`.
2. Після погодження розгорнути на **той самий** Netlify-проєкт: `npx netlify-cli@latest deploy --prod --site ІМЯ-АБО-ID` (або погоджений Git push).
3. Новий worker отримує hash-version, встановлюється у waiting. У застосунку з’являється «Оновити»: після натискання завантажується нова оболонка, старі власні cache-версії прибираються, переглянуті hashed-ресурси мігрують. AsyncStorage/localStorage ніколи не очищаються. Звичайні читачі не виконують reviewer-запити щохвилини.
4. Якщо застряг кеш: онлайн Settings → Repair offline cache. Прибирає тільки service worker та advent caches, не завершені дні/мову. Не радити «очистити всі дані сайту» або перевстановлення для виправлення кешу.

## Фактичні перевірки / межі

- PASS: TypeScript, lint, 10 progress/config tests, структура 24×3 та 162 посилання на ресурси.
- PASS: 3 автоматичні PWA-тести — пароль/підпис/expiry/fail-closed; симульований worker install/offline/update/cache-migration; metadata та 24 HTML маршрути. Це Node/VM-тести, не емулятор телефону.
- PASS: локальна `netlify build --offline` — production web export і пакування `review.cjs`. Не cloud deployment.
- PASS: браузерні розміри 390×844 та 768×1024 — ширина документа дорівнює ширині viewport; карта прокручується у власному контейнері. Це responsive web QA, не перевірка фізичних safe areas/орієнтації iPhone/iPad.
- PASS: реальний локальний браузер — 24 маршрути × UK/EN/RU, на кожному шість вкладок (72 перевірки структури екрана); окремо читання першого/останнього дня й family challenge. Не незалежна редакторська експертиза всіх текстів.
- PASS: неавторизовані Settings не мають Preview; приватна серверна авторизація працює через локальний Netlify-compatible harness (тільки тестовий пароль, не production secret).
- PASS: контрольоване відключення відповідей локального сервера → повторне завантаження й нова вкладка з кешу. Це симуляція втрати мережі, не фізичний airplane mode.
- PASS: два різні worker-релізи → visible Update → reload; обрана мова збережена. У локальній HTML-fixture дати 1 грудня відкрито тільки день 1, завершено звичайним UI, після оновлення й повернення реальної дати він лишився Done, день 2 Locked. Після закриття й нового офлайн-запуску прогрес і мова збережені. Системний годинник не змінювався; fixture не входить у dist.
- PASS: збережені iOS/Android-проєкти, EAS; Hermes-експорт спільного коду для iOS та Android. Попередні локальні native-артефакти не видалено; вони не автоматично перевидалися після останніх PWA-змін.
- НЕ ВИКОНАНО: фізичні Safari/iPhone/iPad, Chrome/Android, справжній Add to Home Screen/standalone launch, фінальний HTTPS/Netlify cloud QA та API-secrets production. Manifest/іконки/інструкції підготовлені; не називаємо metadata-перевірку фізичною інсталяцією.

Блокери: вхід Netlify, згода на публічний deploy, погоджене постійне ім’я/URL, встановлення production reviewer secrets, фінальна перевірка на телефонах. Apple/Google акаунти лишаються окремими блокерами native-публікації, але не PWA.

Журнали цього етапу: pwa-build.log, pwa-tests.log, pwa-release-check.log, pwa-netlify-local-build.log, pwa-native-compat.log, pwa-ui-smoke.json. Фінальний пакет не містить локальних QA date/password fixtures; вони існують лише в scripts/serve-pwa-test.cjs і тестах, не в dist. Стандартний клієнт не має приватного пароля. Перенесення даних між Safari та встановленою іконкою на фізичному iPhone ще не перевірене; для родини варто одразу користуватися постійною встановленою іконкою.
