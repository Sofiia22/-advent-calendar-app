# Dependency/security review — 2026-10-28

Actual registry audit before corrections: 30 advisories (1 critical, 10 high, 10 moderate, 9 low). Compatible `npm audit fix --ignore-scripts` updates removed the critical shell-quote advisory and most high advisories. Expo remains SDK 54 (54.0.38); root Expo Router stays 6.0.24; React Native stays 0.81.5. A same-major PostCSS 8.5.32 override removes its high advisories. No `--force` SDK migration was used.

Final recorded registry audit: **16 advisories: 0 critical, 1 high, 3 moderate, 12 low**. Audit output is `npm-audit-final.json`.

The remaining high advisory is **image-size 1.2.1**, transitive through Metro (build-time image metadata parsing). Its current major 1 has no patched release; major 2 changes the callable API expected by Metro, so it was not forced into the existing SDK. The app does not accept image uploads or process untrusted images at runtime. Mitigation: build only repository-owned illustrations, do not run this toolchain on external/unreviewed image inputs, do not expose development/Metro ports publicly. This limits the identified attack surface, but does not turn a finding into a passed security review. Re-evaluate a compatible patched Metro/Expo toolchain before store submission; test thoroughly if an upgrade becomes necessary.

Static reachability review completed for the three underlying vulnerable libraries and dependency-propagated entries; see DEPENDENCY_REACHABILITY.md. Current Router query-string imports call stringify, not its vulnerable decoder; Expo config/deepmerge operates on local build configuration. No reachable vulnerable decoder call was established in inspected source. Dynamic deep-link/network QA and owner acceptance/remediation of the remaining constrained build-time risk are still pending. Raw advisory counts are not proof that native users are exposed to every finding; successful builds do not prove absence of vulnerabilities.

No credentials, private certificates, upload keys or fake signing identities were created. Only the normal generated Android debug configuration exists; local release signing is hardened to unsigned. Native directories are generated/ignored; use `npm run native:prepare` to reproduce the unsigned local handoff. EAS signing must be configured by the owner via official tooling.

Source/native declaration checks: no ads/analytics integration found; no remote push-token acquisition; church links parent-gated; no request for camera/microphone/contacts/location. Actual Android APK manifest confirms these permissions absent and backup disabled. expo-notifications transitively includes Firebase push components: automatic messaging registration and Analytics collection are now explicitly disabled by a reproducible Expo config plugin and verified in the built APK. This is prevention, not evidence that an earlier version sent data (no Firebase project configuration was found). Actual 26 iOS/Pods privacy manifests declare no tracking/collection. Full physical-device runtime/network validation remains required.
